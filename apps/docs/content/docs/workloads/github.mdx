---
title: GitHub services
description: Build and deploy a branch of a public or private repository.
---

A GitHub service follows one branch of a public or private repository on
github.com. Deploy builds the branch's latest commit and runs it like a
[Docker service](/workloads/docker), with the same environment variables,
volumes, domains, versions and logs.

## Create a service

Choose **Create service → GitHub**, then **Private repository** or **Public
repository** at the top of the dialog. Both continue the same way: pick a
branch, name the service and create it.

### Private repository

A repository a GitHub App is installed on. Connect GitHub first in
**Settings → Integrations** (see [GitHub integration](/settings/github)), then
pick the repository.

### Public repository

Any public repository on github.com, with no GitHub App. Enter it as:

- `owner/name`
- its address, such as `https://github.com/owner/name`, or the address of one
  of its pages, such as `https://github.com/owner/name/tree/dev`
- its clone address, `https://github.com/owner/name.git` or
  `git@github.com:owner/name.git`

Once the repository is found, its branches load with the default branch
picked. A moved or renamed repository is saved under its current name. A
private repository is refused here: add it on the **Private repository** tab.

A service from a public repository deploys only by hand: pushes reach the
platform through a GitHub App (see [Deploy on push](#deploy-on-push)).

### After creation

The repository is fixed. The branch can be changed in the service's
**Configuration**; the next deploy builds the new branch's latest commit.

## How it builds

- With a `Dockerfile` at the root of the branch, it builds that file.
- Without one, [Railpack](https://railpack.com) detects the stack and builds
  it. The app must listen on its domain's port, for example through a `PORT`
  variable set on the service.

Builds run with rootless BuildKit inside the cluster, and images are pushed to
the platform's own registry. The service overview lists builds with their log.
A build can be cancelled from the console.

### Build commands

The **Build** section of **Configuration** overrides Railpack's install, build
and start commands, for example `npm ci`, `npm run build` and `npm run start`.
A `Dockerfile` build ignores them. Changing one rebuilds on the next deploy.

A deploy whose image already comes from the branch's latest commit, built with
the current commands, skips the build.

## Deploy on push

A push to the branch deploys a service that was deployed before. It needs the
GitHub App: a public repository added without one deploys by hand. Turn off
**Deploy on push** in the service's settings to deploy only by hand. A push
during a build cancels that build.

<Callout type="warn">
  GitHub sends pushes only to an HTTPS address, so push deploys need a
  [control plane URL](/settings/control-plane-url). Apps created before
  push deploys must have the **Push** event turned on once in their settings
  on github.com.
</Callout>

## Not supported yet

- A `Dockerfile` path or build context other than the repository root
- Build arguments, and build-time variables for Railpack builds
- GitHub Enterprise Server
