A **project** groups the services of one application: its apps, databases,
sites and buckets. Every project is one private network, isolated from other
projects (see [Private network](/networking/private-network)).

![The storefront project on the Architecture tab: web, api and worker Docker services, a PostgreSQL database and an S3 bucket](/screenshots/project-canvas.png)

## Deploys and versions

Changes to a service's configuration are saved as **pending changes**.
**Apply changes** shows what the next version changes, and which changes
restart the service, then deploys it. The first deploy creates `v1`.

![Apply changes: CPU, memory and replicas changed, four environment variables added, each marked Restarts pods](/screenshots/apply-changes.png)

The **Versions** tab lists every version. Open one to compare it, or
**Roll back** to it. A rollback restores the image, command, resources and
environment; volumes and their data stay as they are.

![The Versions tab of web: v2 is active, v1 can be compared or rolled back to](/screenshots/versions.png)

Domain changes are the exception: they apply at once, without a deploy.

A service can be **stopped**, **started** and **restarted** from its menu.

## Project tabs

| Tab | What it shows |
| --- | --- |
| Architecture | The services of the project on a canvas |
| Usage Metrics | CPU, memory, network, disk and database metrics. See [Logs and metrics](/workloads/logs-and-metrics) |
| Logs | The output of every service in one list |
| Audit Trail | Who changed what in the project, from where, and how it ended |
| Settings | The project's own settings |
