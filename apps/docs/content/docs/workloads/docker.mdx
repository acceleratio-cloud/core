A Docker service runs a container image from any registry the servers can
reach. Create one with a **name** and an **image**, for example
`nginx:latest`.

![The Create Docker service dialog with the name web and the image nginx:1.27-alpine](/screenshots/create-docker-service.png)

## Configuration

The service's **Configuration** tab holds its settings. Saved changes wait as
a pending change until **Apply changes**.

![The Configuration tab of web: 0.5 vCPU and 768 MiB per replica, 2 replicas, a pending change](/screenshots/docker-configuration.png)

| Setting | Meaning |
| --- | --- |
| Image | The image, with a tag or digest |
| Entrypoint | Replaces the image's `ENTRYPOINT` |
| Command | Replaces the image's `CMD`. Split like a shell line; quote arguments that contain spaces |
| Replicas | How many copies of the service run |
| CPU and memory | Limits per replica |
| Node selector | Run only on servers with these labels, one `key=value` per line. Labels are set on the [Servers](/servers) page |

## Environment variables

Edit variables in the **List** editor, one name and value per row, or paste a
whole `.env` file into the **Raw** editor (`KEY=value` per line; lines starting
with `#` are comments). Values stay hidden until you reveal them, and changes
are applied with the next deploy.

![The Environment tab in List mode with five variables, values hidden](/screenshots/environment.png)

## Volumes

Files a service writes are lost when it restarts, unless they are on a
[volume](/storage/volumes). A service can mount up to 10 volumes.

## Domains and private name

Every service gets a generated HTTPS domain and can have custom domains. Other
services in the project reach it by its private name, `<hostname>.internal`.
See [Domains](/networking/domains) and
[Private network](/networking/private-network).

## Terminal

Open a terminal into a running container from the service.
